# 0040 — Turning on the providers' plan tools

- **Context:** the conversation and the worktree strip show the agent's real plan (spec §3, "plano real"). Both CLIs now ship that tool off: Claude Code 2.1.x enables TaskCreate/TaskUpdate/TaskList only for older models unless `CLAUDE_CODE_ENABLE_TODO_TOOLS` is set, and Codex 0.159 only offers `update_plan` with `tools.update_plan.enabled = true`. Agents answered "no todo tool in this session", so no plan ever reached the app. Paseo passes neither.
- **Decision:** the Claude provider adds `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` to the process env as a default under the daemon's own env, and the Codex provider adds `tools: { update_plan: { enabled: true } }` to the thread config unless the provider options already set it. The existing mappers turn them into `todo` timeline items (Claude task results, Codex `turn/plan/updated`). A new Claude prompt also drops tasks an earlier turn completed, since Claude's task list lives as long as the session.
- **Why:** the plan is a v1 feature, and both flags are per-process or per-thread: nothing in `~/.claude` or `~/.codex` is touched. A user who sets the Claude flag in their env keeps their value. A `tools.update_plan` set only in `~/.codex/config.toml` is overridden for Interlock threads; set it in the daemon's Codex provider options to change it.
- **Consequences:** Claude's task tools are deferred, so it calls ToolSearch before its first TaskCreate. Their tool calls still arrive as `tool_call` items next to the plan; the app decides how to show them.
