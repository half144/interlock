# 0020 — Project settings replace `paseo.json` for worktree setup

- **Context:** Paseo reads a repo-level `paseo.json` (committed in the user's repo) for worktree setup commands. Spec decision 10 puts setup in the project settings of the app instead (script, env, files to copy, `.worktreeinclude`), and the user never edits repo files for Interlock.
- **Decision:** project settings live in `~/.interlock/project-settings.json` (`{ version: 1, projects: { <repo root>: settings } }`, atomic writes, keyed by the main repo root so every worktree of a repo shares them). Worktree bootstrap (`prepareWorktreeSetup`) copies the configured files plus the `.worktreeinclude` matches, then runs the setup commands with the project env on top of the worktree runtime env. `paseo.json` is no longer read for setup. Its teardown and `terminals` readers, the `read/write_project_config` RPCs and `seedPaseoConfigFile` stay untouched until the owner decides to drop them.
- **Why:** one source of truth that the app edits and the daemon validates; no surprise execution of commands from a cloned repo's `paseo.json`. Keeping the unrelated `paseo.json` readers avoids rewriting inherited teardown/terminal code and tests that v1 does not touch.
- **Consequences:** a corrupt settings file fails setup with the file path and how to reset it. `.worktreeinclude` follows gitignore syntax and only copies files git ignores (checked with `git check-ignore`), same as Claude Code. Autonomy maps to provider modes in `project-settings/autonomy.ts`: `auto` is Claude `auto` / Codex `auto` (`on-request` + `workspace-write`), `full-auto` is Claude `bypassPermissions` / Codex `full-access` (`never` + `danger-full-access`); a `plan` mode request is kept.
